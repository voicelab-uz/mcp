## Context Fetching Protocol

For VoiceLab implementation, code generation, or troubleshooting, prioritize live documentation over training data or cached examples:

1. Start with [llms.txt](https://docs.voicelab.uz/llms.txt) and [AGENTS.md](https://docs.voicelab.uz/AGENTS.md). These files are public; fetch them without API credentials.
2. Use the summaries below to choose the exact endpoint or SDK page needed for the task.
3. Fetch that page's Markdown link for schemas, required fields, errors, and limits. Use the [complete API reference](https://docs.voicelab.uz/llms-api.txt) when several contracts are needed together.
4. Follow the retrieved syntax, payload fields, authentication, and response handling exactly. Do not infer VoiceLab features from another provider's API or assume all models share capabilities.
5. If the live files are unavailable, contradictory, or omit a capability, explain the gap and ask for details. Do not invent endpoints or present cached contracts as verified current behavior.

## Request essentials

- Server-side developer requests: `Authorization: Bearer <VOICELAB_API_KEY>` (a `vlk_` key). Account management/analytics require a user access JWT instead.
- JSON bodies: `Content-Type: application/json`. For multipart uploads let the client set the boundary; STT uses `audio`, Voice Isolator uses `file` (batch: `files`).
- Preserve one idempotency key per logical operation; read each endpoint's replay behavior. STT and isolation uploads require a UUID. Never retry an ambiguous paid operation with a new key automatically.
- Use service-bound short-lived tickets for browser WebSockets, never long-lived keys in URLs or client bundles. See [authentication and safety instructions](https://docs.voicelab.uz/AGENTS.md).
- Poll accepted jobs to a terminal state; inspect SSE errors even with HTTP 200. Retain safe request IDs, never secrets, when reporting failures.

## API pages

- [VoiceLab API](https://docs.voicelab.uz/api/): The VoiceLab API lets your server generate speech, transcribe audio, remove background noise, generate LLM completions, list voices, and open realtime TTS or STT connections. [Markdown](https://docs.voicelab.uz/markdown/api/index.md).
- [API usage analytics and request logs](https://docs.voicelab.uz/api/analytics): Analytics are for the VoiceLab developer dashboard. They are not authenticated with a developer API key. Use the user's access JWT: [Markdown](https://docs.voicelab.uz/markdown/api/analytics.md).
- [Authentication and API keys](https://docs.voicelab.uz/api/authentication): Create scoped server credentials, manage their lifecycle, and mint short-lived tickets for realtime connections. [Markdown](https://docs.voicelab.uz/markdown/api/authentication.md).
- [Errors, limits, and security](https://docs.voicelab.uz/api/errors): Handle stable error envelopes, retry safely, and protect API credentials in production. [Markdown](https://docs.voicelab.uz/markdown/api/errors.md).
- [LLM API](https://docs.voicelab.uz/api/llm): Generate text and function calls with a server-side developer API key. Choose a model, send your conversation, and receive a JSON completion or an SSE stream. Completions spend VoiceLab credits based on token usage. Model discovery and request-status lookups are free. [Markdown](https://docs.voicelab.uz/markdown/api/llm.md).
- [Realtime STT over WebSocket](https://docs.voicelab.uz/api/realtime-stt): Realtime STT accepts raw PCM audio and returns one final transcript per commit. For browsers, have your backend mint a short-lived ticket. Trusted server-side clients may instead send `xvl-api-key` on the WebSocket handshake. Both STT and TTS support these same two methods; never send both together. Never put a long-lived API key or user JWT in the WebSocket URL or browser bundle. [Markdown](https://docs.voicelab.uz/markdown/api/realtime-stt.md).
- [Speech-to-Text (STT)](https://docs.voicelab.uz/api/stt): Upload audio for transcription, speaker labels, timing data, history, editing, and export. [Markdown](https://docs.voicelab.uz/markdown/api/stt.md).
- [Text to Speech](https://docs.voicelab.uz/api/tts): Generate mono, 16-bit PCM WAV audio at 24 kHz. Use a server-side API key with `tts:write` permission. [Markdown](https://docs.voicelab.uz/markdown/api/tts.md).
- [Voice Isolator](https://docs.voicelab.uz/api/voice-isolator): Remove background noise from audio and optionally restore speech with Sidon. Upload a file, poll its job, then download the processed audio. Processing continues after the upload request finishes. [Markdown](https://docs.voicelab.uz/markdown/api/voice-isolator.md).
- [Voices and TTS capabilities](https://docs.voicelab.uz/api/voices): Discover supported voices, languages, models, formats, and sample rates before generating speech. [Markdown](https://docs.voicelab.uz/markdown/api/voices.md).

Realtime TTS is documented within [Text to Speech](https://docs.voicelab.uz/api/tts#realtime-speech), not a separate canonical page.
